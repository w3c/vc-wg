manu: Manu is not representing these organisations. He is not speaking for them. In the retail sector, typical usecase where DC API doesn't work. How can this happen in a single

click ?

manu: DC API can't do this as many back and forth for issuance and verification. 8-16 taps required. Bad user experience. This has been solved in VCALM which can do issuance and verification in one flow.

<phila> [Manu is sharing his slides in the Zoom channel but they're linked in the minutes]

manu: This is very complicated and creates bad UX. Want platforms and browsers to not block requests that are not of the "right" VC format.

manu: Consistency is required. Third usecase : verifiers must be registered with Apple or Google store. This means that a verifier has to do this for each wallet they want to support. This is difficult for a small retailer.

manu: the ask is to reuse website certificates to verify the verifier.

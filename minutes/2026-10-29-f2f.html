phila: Could you briefly summarize what Confidence Method is?

JoeAndrieu: Confidence method is a property an issuer can add such that a verifier can increase their confidence that a party is the party in the credential. This could be proving in real time that a party interacting with a website is the person a credential is about.
… It could also be comparing what is in a log to what is in a VC - such as with Confidence Method using DIDs.
… There are two other properties we would like for the future - a key based mechanism, which is either a reference to a DID, a reference to a key in a DID, or embedding the key in the VC. We will use the VM from the DID spec, so if you have the VC you don't have to dereference a DID.
… There are also two biometric related confidence methods - a biometric template, where we have gone to a biometric template creator and created a template, then given that to an issuer who has embedded that in the VC.
… When someone presents the VC a biometric confirmation can be performed with the template.
… This is designed to be open-ended and not bottlenecked - ideally the holder of the credential can use any biometric evaluator that is acceptable to them and the verifier.
… Another is the biometric image confidence method, which does not do this templating, but just contains an image for a human or machine to match against.
… This is not particularly robust, but it is a very common mechanism.
… It allows a human to do the confidence without a machine, which is a use case we want to support.
… In addition we have defined an assurance level property which can be applied to any credential subject - an attestation that, before issuance, the issuer achieved some assurance level according to some external standard.
… The credential does not provide this evidence, but the issuer makes the assertion.

JoeAndrieu: I work on threat modeling efforts at W3C to help groups produce threat models. Threat modeling is different than risk analysis - it is about embodied systems. When you do a risk analysis, you may have concerns, say about weather - but you would mitigate different concerns differently. If you can identify risks clearly, you can address risks. But risks are not tied to embodied systems. In threat modeling, you start with a diagram, which represents the scope of the threat model.
… The diagram I am sharing right now is a dataflow diagram without any flows - I am trying to get components that allow realization of our core three confidence methods.
… Walking through the components, we have an issuer with a device that is running a process that will generate a VC with a confidence method in it.
… Ideally this document would be general across all confidence methods - but this is difficult to do, the language is hard to express in an appropriately general way.
… The big blue boxes up top are where you get evaluation done for issuance, and separately there is evaluation done on verification. A biometric template will be evaluated before issuance - and then in near-real time a verifier must get an evaluation done, but those do not need to be done by the same entity.
… On the bottom of this diagram we have the holder's device and a verifier's device - and since DIDs are involved we have a resolver and a data registry.
… I started adding flows about how these systems would talk to each other so we can talk about the threats that those individual flows create. This gets noisy and confusing, and conflicted with the generic language concept. Now we have the holder and the issuer in a flow where the holder is going to biometric template creation that is being provided somehow. Once of the tricks of what I am trying to do in this diagram is have a single diagram that works in different deployment architectures.
… Right now we are exploring four different kinds of deployments. One is everything on-device, in apps or platform tools - not far from putting your fingerprint on your iOS device. People who want better guarantees can have data capture on the phone but evaluation in the cloud.

… Looking at the biometric template creation, whoever runs that controls that service.
… There are also security and trust boundaries at the phone application layer.

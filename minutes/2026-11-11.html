Validation options, JSON schema CR, REs etc

PhilA: I'm talking to David after this call, so will mention it.

Brent: Why are we only talking about validation for Recognized Entities? Why not for VCs as a whole?

Manu: Would it help if I shared what we have right now and do a quick explanation?
… We talked about this on the RE call yesterday. TAG said that the RE task force wants to use JSONata to do validation. We're not sure about that, because it's a small project with only one or two people.
… We replied saying that we had JSON schema, which does some of the work, and proposed that we could support a more generic, arbitrary JavaScript validation process against RE chain.
… We confirmed that it could work for just about everyone. With a generic validator, we can do so without using JSONata specifically.
… We would mark the JavaScript validator and JSONata validator as being at risk but JSON schema validator as not being at risk.
… We felt that this was something that could be applied to VCs more generically, but we could refactor later.

PhilA: When Ivan first proposed that this be moved to VCDM, my initial reaction was that yes, this makes sense, then I ready the very large pull request that Manu created for it.
… I don't think that it makes sense for a single, standalone credential to be able to do this. If you have a single VC that already has a validation mechanism.
… It becomes useful when there's an arbitrary chain of credentials, which can be arbitrarily complex.
… Metrology is an example, which has very complex rules. I think it makes sense there, but not for a single VC.

Ivan: I'm the one who created this mess. I understand that it's too late to do a complex surgery. What I proposed in the issue to do as an alternative is that we already have the notion in VCDM for extensions and vocabularies that are not part of VCDM itself. Eventually, the various vocabularies end up in VCDM. Render Method and Confidence Method

are examples that do this.
… I think we should do something like that for validators as well.
… Maybe in the future we do a cleaner approach, but this is doable for now.
… I understand Phil's problems, but it is still true that RE is not the only place where this might be useful.
… It can be in other applications that we can't think about right now.

KevinDean: Position the idea of a validated state could be useful. A generic validator might not handle everything. A specific use case might have other requirements. However this is a significant change to VCDM. It's fine to continue forward with it in reognized entities for now
